# 04 仕様書(技術者向け)

将来このシステムを修正する人(またはAIアシスタント)向けの設計資料です。

## 1. アーキテクチャ

- Google Apps Script(V8ランタイム)のウェブアプリ。スプレッドシートにバインドされた
  コンテナバインドスクリプト
- フロントエンドは `index.html` + `style.html` + `script.html` の単一ページ構成。
  `google.script.run` でサーバー関数(`api〜`)を呼ぶ
- データストアはスプレッドシートの5シート。ORMはなく、列位置の定数
  (`Code.gs` の `ROSTER_COL` / `GRANT_COL` / `USAGE_COL`)で読み書きする
- 書き込みを伴う処理はすべて `withLock_()`(ScriptLock)内で行い、同時操作による
  不整合を防ぐ。メール送信はロック解放後に行う
- フロントエンドは読み取り系API(`apiGetMyPage` / `apiGetMyRecords` /
  `apiGetGrantTargets` / `apiAdminGetAll`)の結果を**3分間キャッシュ**する
  (`script.html` の `cachedApi`)。申請・承認・名簿変更などの更新系操作の成功時と、
  ヘッダーの「更新」ボタンで全キャッシュを破棄する。残高チェックや承認の確定は
  常にサーバー側で最新のシートに対して行われるため、キャッシュが影響するのは
  表示の鮮度のみ(他人の操作が最大3分遅れて見える)
- 日付・時刻はシート上では文字列(`yyyy-MM-dd` / `H:mm`)。セットアップ時に該当列へ
  テキスト書式(`@`)を設定し、読み出し時にも `normDateStr_` / `normTimeStr_` で正規化する
  (Sheetsの自動型変換への二重の防御)。`google.script.run` は Date を返せないため、
  APIの戻り値はプリミティブのみで構成する

## 2. シート構造

### 設定(キー・バリュー)
| 項目 | 値の例 | 説明 |
|---|---|---|
| 学校名 | ○○小学校 | 表示用 |
| 年度 | 2026 | 年度切替で+1 |
| 勤務開始時刻 / 勤務終了時刻 | 8:30 / 17:00 | 算定の基準 |
| 繰越失効日 | (空) / 2026-06-30 | **空=繰越有効**。値が入ると繰越残は常に0として計算 |
| 管理職への依頼メール / 本人への結果メール | ON / OFF | 通知設定 |

### 名簿
`ID(T001…) / 氏名 / 役職(管理職・主任・教員) / PIN / メールアドレス / 状態(在籍・停止) / 繰越時間(分) / 備考`

- PINは平文では保存しない。`#`+64桁16進のソルト付きSHA-256ハッシュ
  (`hashPin_`: `memberId + ':' + pin + ':' + PIN_SECRET` のダイジェスト)で保存する。
  `PIN_SECRET` はスクリプトプロパティに初回アクセス時自動生成される
- PIN欄に**平文を直接書いた場合も動作**し、次回ログイン成功時に自動でハッシュへ
  置き換えられる(`verifyPin_` の遅延移行)。これはバックアップ復元などで
  `PIN_SECRET` が失われた際の復旧経路を兼ねる(シートのコピーにスクリプト
  プロパティは引き継がれないため、復元後は全ハッシュが照合不能になる。
  その場合は名簿に平文PINを書いてログインすれば新しい鍵で再ハッシュされる)
- 「繰越時間(分)」は年度切替時に自動計算で書き込まれる(年度中の手修正も可)
- 残時間・履歴はすべて**ID**に紐づく(氏名は表示用)。名簿は年度切替でも削除されない。
  新規メンバーのIDは、名簿だけでなく付与・利用記録に残っているIDとも重複しないよう
  発行する(`nextMemberId_`。行削除済みメンバーの記録を別人が引き継ぐ事故の防止)

### 付与記録(1行 = 1教職員への1件の付与)
`付与ID(G00001…) / グループID(GG0001…) / 状態 / 発生日 / 開始時刻 / 終了時刻 / 付与分数 / 事由 / 対象者ID / 対象者氏名 / 起案者ID / 起案者氏名 / 申請日時 / 処理者氏名 / 処理日時 / 処理メモ / 取消者氏名 / 取消日時`

- 1回の起案(会議1件)で対象者の人数分の行が作られ、同じグループIDを持つ

### 利用記録
`利用ID(U00001…) / 状態 / 取得日 / 開始時刻 / 終了時刻 / 利用分数 / 繰越充当分 / 今年度充当分 / 教員ID / 教員氏名 / 備考 / 申請日時 / 処理者氏名 / 処理日時 / 処理メモ / 取消者氏名 / 取消日時`

- 繰越充当分・今年度充当分は**承認時**に確定して書き込まれる(申請時は空)

### 通知ログ
`日時 / 種別 / 宛先 / 件名 / 結果` — メール送信の成否記録(デバッグ用)

## 3. 状態遷移

```
承認待ち ──(管理職)──> 承認済み ──(管理職)──> 取消
   │
   ├─(管理職)──> 却下
   └─(本人/起案者)──> 取下げ
```

- 行は削除しない。すべて状態変更で表現する(監査可能性のため)
- 残時間に影響するのは「承認済み」のみ(取消は除外される)

## 4. 時間の算定ルール(Logic.gs)

- 入力は5分単位・開始<終了を `validateTimeRange` で検証
- 付与分数 = 入力時間帯 −(入力時間帯 ∩ 勤務時間帯) … 勤務時間**外**のみ
- 利用分数 = 入力時間帯 ∩ 勤務時間帯 … 勤務時間**内**のみ
- 0分になる入力は申請時にエラー
- 算定分数は申請時に行へ記録し、以後は再計算しない
  (後から勤務時間設定を変えても過去の記録は変わらない)

## 5. 残時間の計算(Code.gs: computeBalanceMap_)

教職員ごとに:

```
繰越残   = 失効済み ? 0 : max(名簿.繰越時間 − Σ承認済み利用.繰越充当分, 0)
今年度残 = Σ承認済み付与.付与分数 − Σ承認済み利用.今年度充当分
残り合計 = 繰越残 + 今年度残
利用可能 = 残り合計 − Σ承認待ち利用.利用分数
```

- 申請時のチェックは「利用可能」で行う(承認待ちの利用を二重に申請できない)
- 承認時に `allocateUsage`(Logic.gs)で **繰越優先** に充当し、内訳を行に書き込む。
  不足していれば承認はエラーになる(同一バッチ内の複数承認も逐次減算で整合)
- 前年度分と今年度分を区別することで、繰越失効後に今年度残がマイナスになる事故を
  構造的に防いでいる(tests/balance.test.js に要件由来のシナリオテストあり)
- 「今年度残」は付与の強制取消によって負になり得る(管理画面で赤字表示)

## 6. 年次更新

### 年度切替(apiAdminYearSwitch)
1. 人事異動の入力内容と承認待ちを検証(問題があれば何も変更せず中止)
2. `Spreadsheet.copy()` で全体バックアップ(ドライブに保存)
3. 各自の `max(残り合計, 0)` を名簿の「繰越時間(分)」へ書き込み
4. 付与記録・利用記録・通知ログのデータ行を全消去、年度+1、繰越失効日をクリア
5. 人事異動を反映: 転出者(deactivateIds)を「停止」に、転入者(newMembers)を追加し
   初期PINを発行して応答で一度だけ返す

UIは「年次更新」タブのウィザード(`script.html` の `state.wizard`)が
作業選択 → 事前チェック → 人事異動入力 → 最終確認 → 完了 の一本道で案内する。
失効も同じウィザードから実行する。

### 繰越失効(apiAdminExpireCarryover)
- 設定の「繰越失効日」に当日を書くだけ。以後の計算で繰越残が常に0になる
- 取り消したい場合はセルを空にすれば元に戻る(データ自体は変更していないため)
- 失効後に繰越充当を含む利用を取り消した場合、繰越分の充当は復元されない
  (失効済みのため。今年度充当分のみ戻る)

## 7. 認証・セッション

- ログイン: 名簿のIDとPINの照合(在籍のみ・ハッシュ比較、旧平文は成功時に自動移行)。
  5回失敗で5分ロック(CacheService)。PINの初期化(`apiAdminResetPin`)でロックも解除
- PINそのもの・ハッシュ値はクライアントへ一切送らない(管理画面には設定済み/未設定のみ)
- セッション: UUIDトークンを CacheService に6時間保存(操作のたびに延長)。
  クライアントは localStorage に保持し、全APIの第1引数で送る
- セッション切れはサーバーが `AUTH:` 接頭辞付きエラーを投げ、クライアントが
  ログイン画面へ戻す
- 権限: `requireGranter_`(管理職・主任)、`requireAdmin_`(管理職)。
  役職は毎リクエスト名簿から再取得する(役職変更が即時反映される)
- ウェブアプリは「全員(匿名)」公開・「自分として実行」。スプレッドシートへの
  直接アクセス権はユーザーには無く、APIが返すものだけが見える

## 9. 制約・前提

- GASクォータ: メール送信 無料100通/日・Workspace 1,500通/日。実行時間 6分/回。
  数十人規模・年数千行程度なら全く問題ない
- 同時アクセスはScriptLock(最大20秒待ち)で直列化される
- 名前一覧はログイン画面(URLを知っていれば誰でも)に表示される。
  URLの管理が前提のセキュリティモデル
- 過年度データは年度切替時のバックアップコピーが正本
